# V0.1 — dataset validation prototype

The first milestone answers one question: **can we catch obvious annotation-data problems before a reviewer opens the images?**

## Input contract

V0.1 accepts CSV files with these columns:

- `image_id`
- `image_path`
- `label`
- `x_min`, `y_min`, `x_max`, `y_max`

## Checks implemented

The validator currently flags missing required columns, empty IDs/paths/labels, non-numeric coordinates, negative coordinates, invalid box geometry, and exact duplicate annotation rows.

During exercise, treating repeated image IDs as duplicates proved incorrect because one image can contain multiple objects. V0.1 now warns only when the complete annotation row is duplicated. Empty/malformed CSV input and non-finite coordinates are also handled explicitly.

## Manual test data

`data/sample_annotations.csv` is a small clean dataset. `data/messy_annotations.csv` contains deliberately malformed rows so the current behavior can be inspected.

Run:

```bash
python run_qc.py data/sample_annotations.csv
python run_qc.py data/messy_annotations.csv --output reports/messy_report.json
```

The messy file is expected to exit with status 1 because it contains QC errors.

## Not in V0.1

This milestone does **not** claim image-size-aware bounds checking, visual bounding-box review, reviewer actions, a dashboard, or production readiness. Those belong to later milestones after this ingestion/validation layer has been exercised.


## Exercise note

The first exercise exposed a false-positive rule: repeated `image_id` values are normal for object-detection data when one image contains several objects. The validator was changed to flag only exact duplicate annotation rows. Regression tests now preserve that behavior.
