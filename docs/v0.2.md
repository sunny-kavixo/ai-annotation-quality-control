# V0.2 — image-aware boundary checks

V0.1 could tell whether a bounding box had valid geometry, but it could not tell whether a geometrically valid box extended beyond the actual image.

V0.2 starts closing that gap by allowing two optional CSV columns: `image_width` and `image_height`.

When both are present, the validator checks that image dimensions are positive and that `x_max <= image_width` and `y_max <= image_height`.

The columns are optional so existing V0.1 datasets continue to work. Providing only one dimension is treated as a dataset configuration error.

## Exercise dataset

`data/image_bounds_annotations.csv` contains three records. One bounding box intentionally extends past its declared image width, so this dataset should fail with `box_outside_image`.

## Important limitation

This still trusts width and height values supplied by the CSV. It does **not** open the image file and verify its true dimensions yet. That distinction is intentional and will be evaluated before adding image-file inspection.
