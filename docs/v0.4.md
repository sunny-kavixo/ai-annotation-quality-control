# V0.4 — annotation review dashboard

The QC engine now detects structural, image-boundary, and label-quality problems, but JSON alone is awkward for a human reviewer.

This milestone starts a reviewer-facing Streamlit prototype that consumes the **real exported QC report plus its source CSV**. It shows dataset/QC totals, label distribution, issue filtering, row-level annotation data, and optionally renders the selected bounding box over an uploaded source image.

## Why image upload is still manual

A browser dashboard cannot safely assume that paths such as `images/301.jpg` exist on the machine hosting the app. The first slice makes that boundary visible instead of pretending image resolution is solved.

The next exercise should determine a reliable dataset/image loading model, then add tests around the non-UI review data preparation before this milestone is considered complete.


## Reviewer workflow exercised

The initial manual one-image upload did not scale: a reviewer had to browse for every problematic record and could accidentally select the wrong file. The dashboard now accepts one ZIP image bundle whose internal paths match the CSV `image_path` values. Selecting a QC row resolves the correct image automatically.

Review-data preparation and image rendering were extracted into `annotation_qc.review` so they can be regression-tested without launching Streamlit.

Handled failure states now include:

- a QC report row that does not exist in the uploaded CSV;
- a missing image inside the ZIP;
- unsafe traversal paths such as `../secret.png`;
- invalid ZIP/image payloads;
- invalid bounding-box geometry before rendering.

This still does not edit annotations. V0.4 is a review surface; mutation/reviewer decisions should be a later milestone rather than silently changing source datasets.
